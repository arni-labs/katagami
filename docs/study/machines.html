Answers first

These are the leftover phrases. None of them is a contract decision.

D2 — exempt C7, C9, C17, R13 from the prose score

The study scores the same list two ways. Four items on that list are not “how the agent behaved.” They are platform mechanism: C7 is “the DesignLanguage entity is already UnderReview,” C9 is the number ten, C17 and R13 are session-id fields that can be empty strings. A BEHAVIOR.md judge cannot fairly score those. So the prose arm skips them, the machine arm still has them, and we report that as a finding: the machine can say things prose cannot. C19 used to be in that list (“a counter that gated nothing”). The craft machine now gates it at 12, so it is scored.

D5 — judge the Claude Code transcript, not kernel rows alone

Temper’s entity log only records transitions that succeeded. A refused Submit is a 409 in the HTTP response. It never becomes a row on the entity. If the judge only reads kernel rows, the machine’s whole point — it said no — is invisible. Claude Code’s session transcript already contains that 409 as a tool result. So the study judge reads that transcript. Same events, including the denials.

Why I did not install capture hooks in ~/.claude/settings.json

settings.json is global. A SessionEnd hook would fire on every Claude Code session on this machine — mail, other repos, this chat — and upload the whole transcript to Temper. I would not flip that while you were asleep. To turn it on later: merge the snippet in hooks/trajectory-capture/settings.snippet.json into ~/.claude/settings.json, set TEMPER_API_KEY and KATAGAMI_AGENT_ID in the environment, and only then start a study session. Already-open sessions are not captured; the next new session is.

Composite INCOMPLETE at 107k states — why, what to do

The verifier tried to walk CuratorAgent and ReviewAgent together. It explored 107,053 combined states, hit the shipped budget (250,000), stopped, printed INCOMPLETE, and still exited 0. So it did not finish the joint proof, and it looked green. That does not make the machines wrong. It means we do not yet have a finished formal proof of the pair. Do: raise the budget for this verify (a million completed an earlier pair). Do not: treat a green INCOMPLETE as evidence. Not needed for you to review the contract. Not needed to run the LLM-judge study.

Kernel does not persist denials — why, what to do

A 409 is a rejected transition. The entity log is a history of transitions that happened. So the denial lives in the HTTP response, not on the entity. Last night’s smoke: create → 201, illegal submit → 409, and that 409 is in docs/study/evidence/smoke-refusal.json because the harness kept the response. Study: judge transcripts (D5) — already decided. Kernel, later: write a Denied envelope onto the OTS trajectory from the server, so a run that never went through Claude Code still has the refusal. Temper repo, not this PR.

Cross-entity guards are free booleans — why, what to do

When Temper verifies CuratorAgent alone, the guard “DesignLanguage is UnderReview” is not looking at a real DesignLanguage. It is a maybe. So any property that depends on that guard is not actually proved. Runtime still enforces it (the 409 is real). The gap is only the proof. Do: a Temper change so composite verification follows those guards, not only trigger edges. Do not: block the study or your contract review on it. Rita already deferred Layer-1 replay; the study uses the LLM judge.
